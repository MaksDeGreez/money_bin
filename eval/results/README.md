# Evaluation results

Generated by `make eval` (`ml/evaluation/harness.py`); do not edit by hand. Re-running it on the same
inputs gives byte-identical files.

- `index.json`: the inputs (counts and SHA-256 digests of the receipt set and the ground-truth export,
  the seed, the matching weights and thresholds, the version of the name normalisation), every run
  and every comparison. Every file carries `results_version`, the version of this structure.
- `runs/<run id>.json`: one run's aggregate metrics, per segment, with 95% bootstrap intervals.
- `comparisons/<run A>__vs__<run B>.json`: paired differences (A - B) and McNemar's tests.
- `tables/*.md` and `tables/*.csv`: one table per question, generated from the JSON files.

What may be here: numbers, category slugs, model names and run parameters. Never an item name, a
merchant, a receipt id, an amount or a date of a single receipt, or a path on the owner's machine. The
harness's writer (`ml/evaluation/results.py`) accepts only a declared structure and refuses anything
else; per-receipt detail goes to `--diagnostics DIR`, a folder outside git.

Metric definitions, the inputs and how to add a run: `ml/README.md`, "The evaluation harness". The
reasons: `docs/decisions/0014-evaluation-harness.md`.
